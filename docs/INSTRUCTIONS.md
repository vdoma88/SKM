# Инженерные инструкции и стандарты разработки (`INSTRUCTIONS.md`)

Документ задаёт правила проектирования, хранения данных и разработки бренд-нейтрального приложения по подбору твердосплавных пластин (СМП) для токарно-фрезерного и осевого инструмента.

## 1. Базовые стандарты домена

1. **ISO 13399 (Tool Data Representation):**
   - Разделение сущностей на `Cutting Item` (сменная пластина), `Tool Item` (державка, корпус фрезы, корпус U-сверла) и `Assembly` (наладка).
   - Имена расширенных геометрических атрибутов в JSONB (`IC`, `RE`, `S`, `L`, `W1`, `BS`, `EPSR`, `KAPR`, `DC`, `DMIN`, `D1`, `APMX`) строго соответствуют кодам ISO 13399.
2. **ISO 1832 (Обозначение СМП):**
   - Все коды пластин нормализуются в `normalized_code` (удаление пробелов/дефисов, верхний регистр) и раскладываются на структурированные поля.
   - Геометрическая совместимость с посадочным гнездом вычисляется через каноническую сигнатуру:
     `SHAPE-CLEARANCE-IC(x100)-THICKNESS(x100)-FIXING` (пример: `C-N-1270-476-G`).
3. **ISO 513 (Группы обрабатываемых материалов):**
   - Жёстко закреплённая цветовая палитра во всём UI:
     - **P** (Стали) — `#0072CE`
     - **M** (Нержавеющие стали) — `#F2C94C`
     - **K** (Чугуны) — `#EB5757`
     - **N** (Цветные металлы) — `#27AE60`
     - **S** (Жаропрочные и титан) — `#F2994A`
     - **H** (Закалённые стали) — `#828282`

## 2. Правила единиц измерения и физического ядра

- Внутреннее хранилище, API и расчётное ядро работают **исключительно в метрической системе (СИ)**: `мм`, `м/мин`, `об/мин`, `МПа`, `Н`, `кВт`, `Н·м`, `см³/мин`.
- Конвертация в дюймовую систему (`in`, `SFM`, `IPR`, `IPM`, `HP`) выполняется только на уровне отображения GUI.
- Все формулы Кинцле (`app/kienzle.py`) должны покрываться модульными тестами (`tests/test_engine.py`) перед каждым изменением.

## 3. Принцип бренд-нейтральности

- Базовые архетипы сплавов и стружколомов принадлежат виртуальному производителю `GENERIC` (`is_generic = TRUE`).
- Коммерческие каталоги производителей подключаются как внешние данные через таблицу `manufacturers` и сопоставляются через `insert_cross_references` без изменения логики ядра.

## 4. Стандарты кода и коммитов

- Python 3.10+, строгая типизация (Pydantic v2), форматирование PEP 8.
- Все изменения схемы БД фиксируются в `db/schema.sql` и сопровождаются валидными данными в `db/seed.sql`.
- Проверка перед пушем: `pytest -v`.
